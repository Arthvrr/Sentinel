Votre Staff Engineer automatisé.

Ne vous contentez plus de simples linters. Propulsé par le modèle LLM ultra-rapide Gemini 3.8 Flash, Sentinel AI s'intègre nativement à votre flux CI/CD sur GitHub. Il audite vos commits, analyse votre architecture logicielle, traque les failles de sécurité, et vous propose des optimisations de code directement dans vos Pull Requests.

Une intelligence artificielle qui comprend votre projet

Contrairement aux outils classiques qui ne regardent que les lignes modifiées, Sentinel AI utilise un "Super Contexte" pour comprendre les effets de bord de chaque ligne de code que vous tapez.

🌳

1. Arborescence du projet

Sentinel cartographie l'intégralité de vos dossiers et fichiers. Il vérifie que votre nouvelle classe respecte les patrons de conception (MVC, MVVM) et que votre architecture globale reste cohérente et modulaire.

📄

2. Code source intégral

En analysant les fichiers modifiés dans leur globalité, l'IA repère les variables globales oubliées, les imports morts, et s'assure que votre nouvelle fonction ne casse pas la logique métier de la classe.

🔍

3. Analyse du Diff

En superposant le git diff au contexte global, Gemini 3.8 Flash détecte précisément les failles de sécurité, les fuites de mémoire ou la complexité algorithmique (Big O) introduites par votre commit.

Quatre niveaux de sévérité. Zéro compromis.

🚨

[CRITICAL] - Action immédiate requise

Réservé aux failles de sécurité majeures (injections SQL, clés privées exposées, XSS) ou aux bugs critiques qui provoqueront un crash inévitable de l'application en production.

🔴

[HIGH] - Problème d'architecture ou bug majeur

Signale des erreurs de logique métier, des appels réseau bloquants sans timeout, des violations graves du principe de responsabilité unique (SRP), ou des goulets d'étranglement de performance.

🟠

[MEDIUM] - Dette technique & Optimisation

Met en évidence du code dupliqué (DRY), un couplage fort entre composants, des exceptions silencieuses non traitées, ou des opportunités de refactoring pour améliorer la maintenabilité.

🔵

[LOW] - Clean Code & Hygiène

Suggestions concernant le style de code (PEP 8, nommage), l'oubli de fichiers temporaires (ex: .DS_Store), ou l'ajout recommandé de commentaires explicatifs (docstrings).

Installation BYOK (Bring Your Own Key)

La confidentialité avant tout. Sentinel AI s'exécute sur vos propres serveurs GitHub Actions en utilisant votre propre clé API Gemini. Nous n'avons jamais accès à votre code source ni à vos clés de chiffrement.

1

Autoriser la GitHub App

Pour que Sentinel puisse publier ses commentaires sur vos commits, vous devez lui en donner l'autorisation :

  • Rendez-vous sur la page d'installation : Sentinel AI Audit.
  • Cliquez sur le bouton Configure en haut à droite.
  • Sélectionnez le profil personnel ou l'organisation où vous souhaitez installer l'outil.
  • Dans la section Repository access, choisissez Only select repositories et cochez les dépôts spécifiques sur lesquels Sentinel doit auditer le code.
  • Cliquez sur Save.
2

Fournir votre clé API Gemini

Générez une clé API gratuite depuis Google AI Studio.
Dans chaque dépôt GitHub où vous avez activé Sentinel, allez dans :
Settings > Secrets and variables > Actions.
Créez un nouveau secret nommé exactement GEMINI_API_KEY et collez-y votre clé.

3

Déposer le fichier Workflow (Le déclencheur)

Enfin, pour activer l'analyse automatique à chaque push, vous devez créer un fichier sentinel.yml et le placer dans le dossier caché .github/workflows/ de votre dépôt cible (attention, pas à la racine de votre projet !). 



name: Sentinel AI Code Review
on: [push]
permissions:
  contents: write
jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: Arthvrr/Sentinel@master 
        with:
          gemini_api_key: ${{ secrets.GEMINI_API_KEY }}
📄 Copier le fichier source

Besoin de désactiver Sentinel ?

C'est votre code. Vous gardez le contrôle total. Pour stopper les audits d'IA sur un dépôt, vous avez deux options extrêmement simples :

Option 1 : Côté Code

Supprimez simplement le fichier .github/workflows/sentinel.yml. GitHub Actions arrêtera immédiatement de déclencher le bot.

Option 2 : Côté GitHub

Allez dans les paramètres de la GitHub App et décochez le dépôt dans la liste Repository access.
